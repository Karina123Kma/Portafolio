SQL INJECTION LAB

Lab 4

Nombre del laboratorio

SQL injection attack, querying the database type and version on MySQL and Microsoft

Objetivo del laboratorio

El objetivo de este laboratorio es explotar una vulnerabilidad de SQL Injection para obtener información sobre el tipo de base de datos y su versión utilizando un ataque UNION.

En este caso se busca mostrar la versión del servidor de base de datos MySQL o Microsoft SQL Server.

Contexto técnico

La vulnerabilidad se encuentra en el filtro de categorías de productos de la aplicación web.

Cuando el usuario selecciona una categoría, el servidor ejecuta una consulta SQL similar a la siguiente:

SELECT * FROM products WHERE category = 'Gifts' AND released = 1

Debido a que el parámetro category no valida correctamente la entrada del usuario, es posible inyectar código SQL adicional.

Esto permite ejecutar consultas adicionales utilizando UNION SELECT para obtener información de la base de datos.

Payload utilizado

'+UNION+SELECT+@@version,+NULL#

Explicación del payload

El payload utiliza la técnica UNION SELECT para combinar los resultados de la consulta original con una consulta controlada por el atacante.

La variable del sistema @@version permite obtener la versión del servidor de base de datos en MySQL o Microsoft SQL Server.

El valor NULL se utiliza para completar el número de columnas que devuelve la consulta original.

El símbolo # se utiliza para comentar el resto de la consulta SQL original.

Procedimiento

1. Acceder a la aplicación vulnerable desde el navegador.

2. Interceptar la solicitud HTTP usando Burp Suite.

3. Identificar el parámetro category en la solicitud.

4. Determinar el número de columnas que devuelve la consulta original.

5. Verificar qué columnas permiten mostrar datos de texto.

6. Inyectar el payload utilizando UNION SELECT.

7. Analizar la respuesta del servidor para visualizar la versión de la base de datos.

Resultado

Después de enviar el payload, el servidor respondió mostrando la cadena que contiene la versión del sistema de base de datos.

Esto confirma que la vulnerabilidad de SQL Injection fue explotada correctamente utilizando un ataque UNION.
