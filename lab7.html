SQL INJECTION LAB

Lab 7

Nombre del laboratorio

SQL injection UNION attack, determining the number of columns returned by the query

Objetivo del laboratorio

El objetivo de este laboratorio es determinar cuántas columnas devuelve la consulta SQL original para poder realizar ataques UNION correctamente.

Identificar el número de columnas es un paso fundamental antes de extraer información de la base de datos mediante SQL Injection.

Contexto técnico

La vulnerabilidad se encuentra en el filtro de categorías de productos de la aplicación web.

Cuando el usuario selecciona una categoría, el servidor ejecuta una consulta SQL similar a la siguiente:

SELECT * FROM products WHERE category = 'Gifts' AND released = 1

Debido a que el parámetro category no está correctamente validado, es posible inyectar consultas adicionales utilizando UNION SELECT.

Para que una consulta UNION funcione correctamente, el número de columnas debe coincidir con el de la consulta original.

Payloads utilizados

Primer intento:

'+UNION+SELECT+NULL--

Segundo intento:

'+UNION+SELECT+NULL,NULL--

Tercer intento:

'+UNION+SELECT+NULL,NULL,NULL--

Explicación del ataque

Primero se interceptó la petición HTTP utilizando Burp Suite para modificar el parámetro category.

Posteriormente se realizaron múltiples intentos utilizando la cláusula UNION SELECT agregando valores NULL.

Cuando el número de columnas coincide con la consulta original, la aplicación deja de generar errores y muestra contenido adicional en la respuesta.

Esto permite identificar cuántas columnas devuelve la consulta SQL original.

Resultado

Después de probar distintos payloads con valores NULL, se logró identificar el número correcto de columnas devueltas por la consulta.

Esta información es esencial para realizar ataques UNION más avanzados en los siguientes laboratorios.
