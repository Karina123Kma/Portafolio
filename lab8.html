SQL INJECTION LAB

Lab 8

Nombre del laboratorio

SQL injection UNION attack, finding a column containing text

Objetivo del laboratorio

El objetivo de este laboratorio es identificar qué columna de la consulta SQL permite almacenar datos de tipo texto.

Esto es importante porque para extraer información mediante ataques UNION SELECT es necesario encontrar columnas compatibles con datos tipo string.

Contexto técnico

La vulnerabilidad se encuentra en el filtro de categorías de productos de la aplicación web.

Cuando el usuario selecciona una categoría, el servidor ejecuta una consulta SQL similar a la siguiente:

SELECT * FROM products WHERE category = 'Gifts' AND released = 1

Debido a que la entrada del usuario no está correctamente validada, es posible inyectar consultas adicionales utilizando UNION SELECT.

En este laboratorio primero se determina el número de columnas y posteriormente se identifica cuál de ellas acepta datos de tipo texto.

Payloads utilizados

Determinar número de columnas:

'+UNION+SELECT+NULL,NULL,NULL--

Probar columna 1 con texto:

'+UNION+SELECT+'abcdef',NULL,NULL--

Probar columna 2 con texto:

'+UNION+SELECT+NULL,'abcdef',NULL--

Probar columna 3 con texto:

'+UNION+SELECT+NULL,NULL,'abcdef'--

Explicación del ataque

Primero se interceptó la solicitud utilizando Burp Suite para modificar el parámetro category.

Posteriormente se utilizó una inyección UNION SELECT con valores NULL para determinar que la consulta original devuelve tres columnas.

Después se reemplazó cada valor NULL por una cadena de texto para identificar cuál columna es compatible con datos tipo string.

Cuando el valor de texto aparece en la respuesta de la aplicación, se confirma que esa columna acepta datos de tipo texto.

Resultado

Se logró identificar correctamente la columna que acepta datos de tipo texto dentro de la consulta SQL.

Esta información es esencial para realizar ataques más avanzados en los siguientes laboratorios, donde se extraerán datos de la base de datos.
