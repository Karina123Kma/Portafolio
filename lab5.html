SQL INJECTION LAB

Lab 5

Nombre del laboratorio

SQL injection attack, listing the database contents on non-Oracle databases

Objetivo del laboratorio

El objetivo de este laboratorio es explotar una vulnerabilidad de SQL Injection para enumerar el contenido de la base de datos y obtener información sensible.

El atacante debe identificar la tabla que contiene las credenciales de los usuarios y recuperar los nombres de usuario y contraseñas almacenados en la base de datos.

Contexto técnico

La vulnerabilidad se encuentra en el filtro de categorías de productos de la aplicación web.

Cuando el usuario selecciona una categoría, el servidor ejecuta una consulta SQL similar a la siguiente:

SELECT * FROM products WHERE category = 'Gifts' AND released = 1

Debido a que el parámetro category no valida correctamente la entrada del usuario, es posible inyectar consultas SQL adicionales utilizando UNION SELECT.

Esto permite consultar las tablas del sistema para obtener información sobre las tablas y columnas de la base de datos.

Payloads utilizados

Determinar columnas:

'+UNION+SELECT+'abc','def'--

Listar tablas de la base de datos:

'+UNION+SELECT+table_name,+NULL+FROM+information_schema.tables--

Listar columnas de la tabla de usuarios:

'+UNION+SELECT+column_name,+NULL+FROM+information_schema.columns+WHERE+table_name='users_abcdef'--

Obtener credenciales:

'+UNION+SELECT+username_abcdef,+password_abcdef+FROM+users_abcdef--

Explicación del ataque

Primero se identificó el número de columnas que devuelve la consulta original utilizando UNION SELECT.

Posteriormente se consultó la tabla information_schema.tables para obtener los nombres de todas las tablas de la base de datos.

Una vez identificada la tabla que contenía las credenciales de los usuarios, se consultó la tabla information_schema.columns para descubrir los nombres de sus columnas.

Finalmente se realizó otra consulta UNION para obtener los nombres de usuario y contraseñas almacenados en la tabla.

Resultado

Después de ejecutar los payloads, se obtuvieron las credenciales de todos los usuarios registrados en la base de datos.

Con la contraseña del usuario administrator fue posible iniciar sesión en la aplicación y resolver el laboratorio.
